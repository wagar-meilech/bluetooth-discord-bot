# Implement native tray controls and scoped container lifecycle

Parent spec: https://github.com/wagar-meilech/bluetooth-discord-bot/issues/2
Local ID: BDB-009
Depends on: [BDB-008 (#6)](https://github.com/wagar-meilech/bluetooth-discord-bot/issues/6)

## Purpose and scope

After the complete feasibility gate passes, build the product host shell using existing tray/menu libraries and proven native adapters. Keep the primary phone-as-speaker path simple.

## Acceptance criteria

- macOS menu-bar and Windows tray status/settings, local approved app/source selection and operator-only pairing.
- Manual startup default, optional OS auto-start, receiver/container readiness status and explicit Discord join requirement after fresh launch.
- Use existing Docker lifecycle tooling; manage only this application's resources and provide actionable Docker/permission errors.
- Store configuration outside image/source and use OS credential storage where practical.
- Silent local default and opt-in monitoring control.
- Stop/Quit cancel forwarding/recovery and clean up owned resources while preserving saved settings/pairings and unrelated workloads.

## Test seam and validation

Approved public session/control boundary for behavior; installed-system seam for OS permissions, tray lifecycle, packaging and real-device regression. Do not mirror vendor tray APIs with wrapper tests.
