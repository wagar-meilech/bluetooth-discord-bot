# Build the minimal local audio-to-Discord feasibility harness

Parent spec: https://github.com/wagar-meilech/bluetooth-discord-bot/issues/2
Local ID: BDB-007
Depends on: [BDB-005 (#3)](https://github.com/wagar-meilech/bluetooth-discord-bot/issues/3), [BDB-006 (#4)](https://github.com/wagar-meilech/bluetooth-discord-bot/issues/4)

## Purpose and scope

Reuse Serenity/Poise/Songbird, including DAVE/Opus/RawAdapter, for a minimal local containerized voice harness. Reuse native OS input paths proven by the prerequisites; keep custom code focused on a bounded local authenticated audio/control bridge.

## Acceptance criteria

- Resolve compatible released dependencies in a lockfile; build the Rust core container through existing Docker tooling.
- Forward live native input to a real server voice channel using the current Discord voice protocol.
- Exercise join/rejoin and member changes, without implementing Discord encryption/codecs manually.
- Expose only the public bridge-session control/audio-input boundary; maintain bounded audio and drop stale data.
- Keep pairing, credentials and app selection local; no whole-desktop fallback or public remote ingestion.
- Provide observable stop and status sufficient to run hardware validation; defer polished UI.

## Test seam and validation

Approved public session/input boundary with external OS/Discord endpoints substituted, using vertical TDD slices. Real voice and native/container networking are validated at the installed-system seam. Container build and synthetic input alone do not establish native Bluetooth.
