# Package, document, and validate the complete private bridge

Parent spec: https://github.com/wagar-meilech/bluetooth-discord-bot/issues/2
Local ID: BDB-011
Depends on: [BDB-009 (#7)](https://github.com/wagar-meilech/bluetooth-discord-bot/issues/7), [BDB-010 (#8)](https://github.com/wagar-meilech/bluetooth-discord-bot/issues/8)

## Purpose and scope

Package the approved host apps and local core, document setup and operating limits, and rerun the hardware acceptance matrix against the completed product. Use existing build/packaging components and keep real evidence separate from reported task state.

## Acceptance criteria

- Repeatable Rust dependency lock/toolchain, Docker build, host startup/setup and concise operating instructions.
- One-time bot credentials and approved server/users set locally; no credentials in source, images or logs.
- Document supported recorded hardware/OS configurations, Bluetooth coexistence baseline, permission flow, source isolation limits and troubleshooting.
- Confirm primary phone playback and alternate selected-app path, monitoring, trusted controls, stop/idle/recovery on both hosts.
- Resolve code-review findings, record relevant tests/builds and actual hardware outcomes, and mark the integration PR ready for review.
- Do not claim a merge, universal device support or hardware test that was not observed.

## Test seam and validation

Both approved seams: public session/input regression plus installed-system acceptance on the recorded matrix. Review final changes as a unit and retain auditable evidence.
