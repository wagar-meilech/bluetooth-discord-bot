# Prove Windows Bluetooth input, isolation, and coexistence

Parent spec: https://github.com/wagar-meilech/bluetooth-discord-bot/issues/2
Local ID: BDB-006
Depends on: None

## Purpose and scope

The Mac candidate has been investigated first and remains blocked on requested-PSM-dependent publication. Advance this independent Windows feasibility leg using official Windows Rust bindings for AudioPlaybackConnection and capture APIs. Evaluate existing receiver behavior and the reported Line (A2DP SNK) recording endpoint before inventing a virtual driver. The full product still requires both native platform paths to pass the common hardware gate.

## Acceptance criteria

- Run on Windows 11+ using a real intended phone and built-in Bluetooth.
- Obtain live audio suitable for forwarding, isolated from Discord and unrelated desktop output.
- Demonstrate silent default forwarding and optional local monitoring.
- Verify other host Bluetooth devices and headset microphone/output against the agreed baseline, with incoming phone audio unaffected.
- Record actual devices, API path and outcomes; endpoint availability is a hypothesis until observed.
- Stop and report any required-path failure without accepting an unapproved platform/hardware workaround.

## Test seam and validation

Installed-system/native hardware boundary, plus the approved bridge-session boundary for externally observable behavior. Use independent test audio and actual Windows evidence; cross-compilation does not pass the gate.

## Current implementation and evidence

A Windows Rust probe now provides nonmutating API preflight, paired-source
selection, bounded receiver activation/cleanup, and read-only capture-endpoint
inventory. It uses official Windows bindings; its receive baseline plays locally
and does not capture or forward PCM.

Windows-target Clippy and the actual Windows release build passed.
[CI run 42543599395](https://github.com/wagar-meilech/bluetooth-discord-bot/actions/runs/42543599395)
produced the x86_64 executable, instructions, checksum and build metadata. The
downloaded binary's SHA256 and PE architecture were verified. Real Windows/phone
results are still required; the ticket remains open/blocked pending that evidence.

Use the [hardware results form](../feasibility/windows-hardware-results.md) and
[full run guide](../feasibility/windows-receiver-probe.md). Full product work still
requires both native platforms and the complete source-to-Discord gate.
