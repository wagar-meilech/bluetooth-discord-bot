# Prove Windows Bluetooth input, isolation, and coexistence

Parent spec: https://github.com/wagar-meilech/bluetooth-discord-bot/issues/2
Local ID: BDB-006
Depends on: [BDB-005 (#3)](https://github.com/wagar-meilech/bluetooth-discord-bot/issues/3)

## Purpose and scope

After the Mac feasibility prerequisite passes, reuse official Windows Rust bindings for AudioPlaybackConnection and capture APIs. Evaluate existing receiver behavior and the reported Line (A2DP SNK) recording endpoint before inventing a virtual driver.

## Acceptance criteria

- Run on Windows 11+ using a real intended phone and built-in Bluetooth.
- Obtain live audio suitable for forwarding, isolated from Discord and unrelated desktop output.
- Demonstrate silent default forwarding and optional local monitoring.
- Verify other host Bluetooth devices and headset microphone/output against the agreed baseline, with incoming phone audio unaffected.
- Record actual devices, API path and outcomes; endpoint availability is a hypothesis until observed.
- Stop and report any required-path failure without accepting an unapproved platform/hardware workaround.

## Test seam and validation

Installed-system/native hardware boundary, plus the approved bridge-session boundary for externally observable behavior. Use independent test audio and actual Windows evidence; cross-compilation does not pass the gate.
