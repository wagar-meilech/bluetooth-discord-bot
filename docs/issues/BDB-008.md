# Record the complete two-platform hardware feasibility gate

Parent spec: https://github.com/wagar-meilech/bluetooth-discord-bot/issues/2
Local ID: BDB-008
Depends on: [BDB-005 (#3)](https://github.com/wagar-meilech/bluetooth-discord-bot/issues/3), [BDB-006 (#4)](https://github.com/wagar-meilech/bluetooth-discord-bot/issues/4), [BDB-007 (#5)](https://github.com/wagar-meilech/bluetooth-discord-bot/issues/5)

## Purpose and scope

Run the Q24 gate against the installed native adapters and local container on both required hosts. This issue is the explicit release of the full-application implementation frontier; a compile, mock or partial registration cannot close it.

## Acceptance criteria

- Real source phone -> built-in receiver -> native adapter -> local container -> real Discord listener on macOS 14.2+ and Windows 11+.
- Current encrypted voice, join/rejoin and member changes exercised.
- Silent local default, optional monitoring and safe isolated host-application input demonstrated.
- Other Bluetooth speakers/headphones/headset microphone/peripherals and incoming source remain usable relative to the normal-call baseline.
- At least 30 minutes per host, plus source switching/loss, bounded network recovery and explicit stop.
- Record hardware/OSes, delay, dropouts and resource behavior; exploratory one-second delay target reported as measured or unmet.
- Required failure stops the full build and is reported with evidence/options. No silent external-device, transport or platform substitution.

## Test seam and validation

Approved installed-system source-to-listener seam. Attach an evidence matrix distinguishing pass, fail, pending and untested. Manual actions/outcomes require explicit operator evidence.
